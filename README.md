# agent-guide

一份可复用的 AI 编程助手默认指令，涵盖授权边界、开发、审查、验证与交付。

**[查看并复制规范正文](prompts/AGENTS.md)** · [变更记录](CHANGELOG.md) · [MIT 许可证](LICENSE)

## 这份规范解决什么问题

这份规范面向日常开发、修复、代码审查和 CI 维护，表达人与 AI 编程助手协作时的默认约定：

- 区分分析、审查与实现请求，按明确目标完成工作。
- 分别管理本地修改、提交、推送、PR、合并和发布的授权。
- 保护工作区既有修改，优先采用满足当前需求的最小完整方案。
- 通过实际验证交付结果，明确说明失败、限制和未验证部分。
- 仅在相关任务中应用多代理、CI 等专项规则，避免无关扩展。

这些规则表达协作期望，执行效果受模型、工具能力、平台指令和权限机制影响。提示词中的授权约定不能代替沙箱、审批和访问控制。

## 仓库结构

```text
agent-guide/
├── README.md             # 定位、使用和维护方式
├── prompts/
│   └── AGENTS.md          # 唯一权威正文，供复制使用
├── CHANGELOG.md          # 影响使用者的变更
└── LICENSE               # MIT 许可证
```

规范放在 `prompts/AGENTS.md`，便于独立分享。仅克隆此仓库，不会将它安装为所有项目的默认指令；需要按所用工具的机制复制或配置。根目录暂不另放一份重复正文。

## 使用方式

### Codex：个人全局默认指令

1. 打开 [prompts/AGENTS.md](prompts/AGENTS.md)，先阅读并按自己的工作习惯调整。
2. 找到 Codex 主目录：默认是 `~/.codex`；如果设置了 `CODEX_HOME`，则使用该目录。
3. 将正文保存为该目录中的 `AGENTS.md`。若已有文件，先备份，再合并相关内容，避免直接覆盖。
4. 检查同目录是否存在非空的 `AGENTS.override.md`。Codex 会优先读取它，此时不会读取同目录的 `AGENTS.md`。
5. 在目标项目启动新的 Codex 会话，检查加载结果。

Windows 默认位置为 `%USERPROFILE%\.codex\AGENTS.md`，macOS / Linux 默认位置为 `~/.codex/AGENTS.md`。

### Codex：只对某个项目使用

将正文合并到目标仓库根目录的 `AGENTS.md`，并补充该项目真实的技术栈、构建入口、业务约束和验证方式。已有项目指令时先备份、比较并合并，不直接替换。

Codex 会从项目根目录向当前工作目录逐层发现指令，每个目录最多采用一份文件：优先 `AGENTS.override.md`，其次 `AGENTS.md`，然后是配置的备用文件名。更深目录的指令可以覆盖前面的约定。规范中的默认值仍须服从平台指令层级及适用的用户和项目要求。

通常选择全局安装或项目安装中的一种即可，避免重复加载同一份长正文。

### 检查是否生效

在新会话中提出只读请求，例如：

> 请列出你本次加载的指令文件，并概括默认语言、提交授权和验证要求。只读检查，不修改文件。

如果没有读到预期文件，检查 Codex 主目录、当前工作目录、覆盖文件和内容是否为空，再重启会话。助手的回答可以辅助检查；需要进一步核实时，参考官方文档中的日志检查方法。

注意长度限制：官方文档说明 `project_doc_max_bytes` 默认值为 32 KiB，达到指令合并上限后可能无法加载完整内容。合并其他指令时应检查总长度；需要时按官方说明调整配置或按真实目录职责拆分。Markdown 链接不会自动使被链接正文成为已加载指令。

加载机制和排查方法依据 [OpenAI 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)，核对日期：2026-10-15。此处核对了文档，尚未针对不同客户端版本完成独立安装与行为测试；其他 AI 编程工具的自动发现方式也尚未验证，请以各工具的官方说明为准。

## 建议按需调整的默认值

| 默认约定 | 使用前需要考虑什么 |
| --- | --- |
| 回复、文档和提交说明默认中文 | 是否符合团队语言约定 |
| 未明确要求时不创建提交 | 是否符合个人或团队的提交流程 |
| 提交、推送、PR、合并和发布分别授权 | 是否需要为明确范围授予本次会话持续授权 |
| 分支采用 `<type>/<short-description>`，提交标题采用类型前缀和中文简述 | 是否已有项目命名规范 |
| 按任务性质选择验证范围 | 项目有哪些必须执行的真实检查入口 |
| 在适用且有收益时使用子代理 | 所用平台是否支持，以及是否有额外成本或限制 |

不要在共享正文中填写密钥、账号凭据、私有环境配置或只能在个人电脑上使用的绝对路径。项目专属说明优先放在对应项目中。

## 如何维护

- 只在 [prompts/AGENTS.md](prompts/AGENTS.md) 维护权威正文，避免多个副本互相漂移。
- 变更优先解决真实协作中出现的歧义或失败，不因一次异常不断叠加规则。
- 修改行为时同步更新 [CHANGELOG.md](CHANGELOG.md)，说明使用者会遇到什么变化及调整原因；安装和默认值变化时同步更新本页。
- 版本从 `0.1.0` 起规划：不改变行为的文字修正使用补丁版本，兼容性规则新增使用次版本；授权默认值等不兼容变化应明确标记并说明迁移方式。`0.x` 阶段可提升次版本，稳定后不兼容变化提升主版本。
- 版本号写入变更记录不代表已创建 tag 或 Release。未发布内容放在“未发布”下，正式发布时再记录版本与日期。
- 分享持续更新的内容可以链接主分支；教程、团队约定和问题复现应使用实际存在的 tag 或 commit 固定链接，并记录自己使用的版本。

评估重要变更时，可以使用这些小场景核对行为：

| 场景 | 期望行为 |
| --- | --- |
| 用户说“审查这段代码” | 只读检查，报告有证据的问题 |
| 用户说“修复这个问题” | 完成必要修改和验证，不停留在建议 |
| 工作区已有无关修改 | 保留原有修改，只处理本次范围 |
| 用户授权提交，未授权推送 | 完成本地提交，停止远端写入 |
| 测试因环境问题无法运行 | 说明限制，不宣称测试通过 |
| 简单文本调整 | 进行相称检查，不扩展成全面审计 |

以上是维护时的行为检查清单，尚未构成自动化评测或通过证明。
